# ox-llm v0.2.1 (draft)

Draft release notes, built from the pull requests merged since v0.2.0 (2026-11-15). The owner
edits and publishes the final text with the tag.

v0.2.1 is the Rust-only release. The Python controller is gone: `oxa` is the front door, it talks
to the cloud providers itself, and it starts the `oxe` engine for local models itself. There is no
daemon and no service to run. Start with the [README](../../README.md) and
[install.md](../../oxa/docs/pages/install.md).

## Upgrading from v0.2.0

- Stop the old runtime, install v0.2.1 and start `oxa` directly. Nothing listens on the old
  controller address any more, and the `oxc` command is gone.
- Provider keys and the ChatGPT sign-in are reused where they are (`~/.config/oxc/llm/`).
- Model settings are not translated. Set up cloud and local models again with the
  [quickstart](../../oxa/docs/pages/quickstart.md). Sessions and caches may start cold.
- The step-by-step guide is [NATIVE-INSTALL.md](../NATIVE-INSTALL.md).

## One product, no Python

- The release archives and packages hold native binaries only: `oxa`, `oxe` and `oxe-server`.
  Every release asset is checked for Python before it is published.
- The Python controller's installer, diagnostics commands and tests are removed. Its source tree
  goes with the last cleanup (see the end of this page).
- The built-in `ox-llm` skill and `oxa report-issue` work with `oxa` alone.
- Release staging, licence collection and the release checks run as shell scripts.

## Cloud models

- oxa has its own cloud gateway. Providers: OpenCode Go, OpenRouter, OpenAI, Anthropic and a
  ChatGPT plan (`oxa login chatgpt --experimental`, `oxa logout chatgpt`).
- An OpenCode Go key in the key file is enough to use Go. Go usage windows and reported paid
  charges are recorded.
- Optional model discovery for OpenRouter, OpenAI and Anthropic (`oxa.cloud.discover_models`),
  with a disk cache.
- Budgets are your choice. With no `oxa.cloud.daily_budget_usd` there is no budget check, and
  every request is still written to the private ledger. With a budget, reservations are atomic
  across processes and restarts.
- OpenRouter requests settle at the cost the provider reports. Models without a known price can
  be given your own rates.
- Subscription limits for Go warn at 80% and 100% and do not stop the request.
- The thinking level is sent to cloud models. Cloud sessions use their own compaction profile
  (`compaction.profile`).
- The gateway refuses to send a request that contains one of your stored keys.
- `oxa usage --json` prints today's spend and request sums. `--usage-log <file>` writes one line
  per model call.

## Local models

- oxa owns the local engine: it starts `oxe-server` on the first request, queues requests fairly,
  switches models, unloads after an idle period and stops the engine under memory pressure.
- A model loads only when free memory covers the weights and the context. The engine runs without
  swap.
- oxa finds the engine beside its own binary, checks that the versions match and explains missing
  weights. It never downloads a model.
- Per-model launch profiles, with sampled MTP defaults for the two reference 35B models.
- The boot helper for the memory-latency kernel setup is now a native tool.

## The agent

- **Goals.** `/goal` and `--goal` set a goal that the session pursues until it is complete or
  blocked. Goal state is saved with the session, survives a restart, and a pause shows its reason.
- **Memory.** A per-entry memory store, with `oxa memory list`, `show` and `rm`.
- **Waiting.** The `wait` tool wakes on real events (new input, CI finished, a pull request
  merged) instead of polling. `oxa send <session> "text"` queues a follow-up for a running
  session, including a headless goal run.
- **Unattended runs.** Print sessions announce their id and can be continued by it. Typed results
  on stderr, a token budget with a clean wrap-up, schema-checked final answers, a stall signal
  (`oxa status <session>`), and automatic resend after a cut stream.
- **Done checks** also run after changes made by bash, subagents, MCP tools and extensions.
- **Subagents** can use their own model, and children on cloud models run at the same time.
- **Repeat guard.** A repeating tool call gets a warning and the run continues. `oxa.maxTurns` is
  the cap.
- **Interface.** `/help` and `/usage`; unknown slash commands are refused locally; a
  budget meter in the HUD; code fences in labelled frames; clearer cancel and exit hints; many
  fixes for paste, narrow terminals and terminal loss.
- **Settings.** Changed settings files apply to a running session. `--no-<tool>` switches and
  `--animation`.
- **Compaction** keeps identifiers word for word in its summaries.
- **Help.** `oxa help <command>` and `--help` on every subcommand, answered without touching
  settings or the network.

## Modes and the sandbox

- The sandbox denies more credential files (package registries, cloud CLIs, build tools, age
  keys), and the file tools open exactly the location the permission check judged.
- `edit` replaces a file atomically.
- Bash: `GH_TOKEN` reaches only the commands that run `gh`; a writable per-session scratch
  directory and cache home; working `mise`, `sccache` and Cargo cache setups; a background job
  can be killed by id; clearer notes when a command fails because of the sandbox.
- Limits are owner settings with generous defaults: `oxa.bash.maxJobs`,
  `oxa.subagent.maxChildren`, and `timeout: 0` for no timeout.
- The mode text and the status bar never claim a sandbox that is not there.

## Work, lead and the board

- `oxa work` runs tasks in separate git worktrees with acceptance checks, a task queue, saved
  checkpoints and recovery. A task without a passing check stays unverified.
- A worker follows your own mode: it runs in yolo only when your user settings say so.
- `oxa work board` reads pull requests, reviews and checks into one board, with leases and claims
  so two workers never take the same item.
- `oxa lead` is a dedicated session for the owner: chat, status, asks and proposals, with an
  optional loopback web page (`oxa lead serve`). Off by default.
- `oxa report-issue` checks a report against current `main` and against existing issues before it
  posts.

## ox AI panel

- The panel moved next to oxa (`oxa/omarchy-panel/`) and has a frozen data contract: it runs only
  `oxa` and reads the JSON that `oxa` prints. The first feed, `oxa usage --json`, is in this
  release. The panel is not packaged yet.

## macOS (groundwork)

- First parts of a macOS port for Apple silicon, for cloud models: bash without an OS sandbox
  (oxa says so at start and in the status bar), MCP servers over stdio, and the ChatGPT token
  store.
- A verified dev installer, `tools/lab/dev-update-macos.sh`.
- Not usable yet: `main` does not build on macOS, and no macOS asset is published.

## Engine

- Sampled decoding can use MTP speculation (`--mtp-sampled`, off by default).
- Reasoning can be bounded per request. Stop strings are capped, and seed `-1` is random.
- Sturdier state cache: budgets enforced without repeated disk walks, recovery after an engine
  error during idle re-prefill, and a busy answer instead of a blocked request.
- A bad request is rejected before it interrupts background work.
- Every `OXE_`, `OXF_` and `OXI_` environment name is documented.
- Proof binaries and unused tools are removed from the engine tree.

## Packaging and releases

- Combined archives for ARM64 and x86_64, each with `SHA256SUMS`, an SBOM and build provenance.
- A rolling `dev` build from every push to `main`, installed with `tools/lab/dev-update.sh`
  beside a stable install.
- Arch recipes for a binary package and a source package.

## Not in the release binaries

- LAN sharing of models (`oxa share`) is in the source tree behind a build feature. The release
  binaries do not include it.
- Image generation (`oxi`) and the Flash engine are not in the combined archive.
