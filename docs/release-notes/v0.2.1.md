# ox-llm v0.2.1 (draft)

Draft release notes, built from the pull requests merged since v0.2.0 (2026-11-15). The owner
edits and publishes the final text with the tag. Items marked "(pending merge)" are open pull
requests planned for this release. Remove them from the notes if they do not merge.

v0.2.1 is the Rust-only release. The Python controller is gone. `oxa` is the front door: it talks
to the cloud providers itself, starts the `oxe` engine for local models itself, and runs workers.
There is no daemon and no service to run. Start with the [README](../../README.md) and
[install.md](../../oxa/docs/pages/install.md).

## Highlights

- **Rust only.** The Python controller, its installer and its tests are deleted. Release archives
  hold native binaries only, and every release asset is checked for Python.
- **Workers.** A `worker` tool starts, lists, stops, messages and resumes workers in their own git
  worktrees. The live Lead session can start workers too. Workers inherit the lead's permission
  level and publish their own branch (pending merge).
- **Keys just work.** An OpenRouter, OpenAI or Anthropic key, or a ChatGPT sign-in, is enough. No
  extra switch, no hand-written model limits.
- **Live model data.** Model lists come from the providers' own endpoints. Nothing is hard-coded.
  The ChatGPT plan list is live too (pending merge).
- **Local models are easier.** `oxa local add model.gguf` sets up a model from the engine's own
  report. Small dense Qwen3.5 models (0.8B and up) now run in `oxe`.
- **Limits warn, they do not block.** Job and subagent caps, token budgets, subscription limits and
  the goal idle pause now warn and keep going. Retries default to 10.
- **Safer by default where it matters.** Publishing refuses commits that add secrets, an unusable
  settings file fails safe offline, and a typed yes only answers a dialog that was shown.
- **`wait` in every session**, and a plain sandbox rule: interactive runs have no OS sandbox and
  dangerous commands ask; unattended runs keep the sandbox.

## Upgrading from v0.2.0

- Stop the old runtime, install v0.2.1 and start `oxa` directly. Nothing listens on the old
  controller address any more, and the `oxc` command is gone.
- Provider keys and the ChatGPT sign-in are reused where they are (`~/.config/oxc/llm/`).
- Model settings are not translated. Set up cloud and local models again with the
  [quickstart](../../oxa/docs/pages/quickstart.md). Sessions and caches may start cold.
- The step-by-step guide is [NATIVE-INSTALL.md](../NATIVE-INSTALL.md).

## Agents and workers

- **Worker tool.** `worker` has `start`, `list`, `stop`, `send`. Each worker gets its own git
  worktree and branch `agent/<name>`, a goal file and a log. `oxa.workers.max` caps live workers.
- **Send and resume.** `send` queues text for a running worker. When you reopen a session, workers
  that died without being stopped are relaunched where they left off, once per session.
- **Lead starts workers.** The live owner Lead session has the `worker` tool. `oxa lead` is a
  dedicated session with chat, status, asks and proposals, and an optional loopback web page
  (`oxa lead serve`). Lead shadow mode is now on by default (set `oxa.lead.shadow` false to opt out).
- **Wait everywhere.** The `wait` tool is available in every session, not only during a goal. It
  wakes on real events: new input, CI finished, a pull request merged, a background job done. Turn
  it off with `oxa.tools.wait: false`. `oxa send <session> "text"` queues a follow-up for any
  running session, including a headless goal run.
- **Mode and sandbox standard.** Interactive runs have no OS sandbox on Linux; dangerous commands
  ask (once, for the session, always, or deny). Unattended runs (subagents, lead workers,
  `oxa work`, headless goals) keep the sandbox. `--sandbox` turns it on for an interactive run.
  Yolo never asks. The mode text and the status bar say what is really in force.
- **Workers follow your mode.** `oxa work` passes the owner's yolo mode to its workers.
  Workers inherit the lead's level (yolo, auto, workspace or plan); an explicit narrower mode
  wins, a wider one is clamped (pending merge).
- **Publishing.** In workspace and auto modes a worker can push its own branch and manage its own
  pull request without a question. Pushes to the default branch, force pushes, other remotes,
  merges and anything chained with a publish command still ask. Yolo is unchanged (pending merge).
- **Work and board.** `oxa work` runs tasks with acceptance checks, a queue, checkpoints and
  recovery. A task without a passing check stays unverified. `oxa work board` reads pull requests,
  reviews and checks into one board with claims so two workers never take the same item.
- **Goals and unattended runs.** `/goal` and `--goal` (also in the TUI) survive restarts and show
  why a goal paused. Print sessions announce their id, report typed results, honour token budgets,
  and resend after a cut stream. A repeating tool call warns and continues. Headless runs get one
  nudge when a reply ends with a plan or promise instead of work.
- **Other.** Per-entry memory (`oxa memory list|show|rm`). A bash command that passes its timeout
  can move to a background job. Done checks also run after changes made by bash, subagents, MCP
  tools and extensions. `read` returns images to models that take them. Compaction keeps
  identifiers word for word.

## Models and providers

- **Keys just work.** An OpenRouter, OpenAI or Anthropic key, or `oxa login chatgpt --experimental`,
  opens the cloud gateway and model discovery by itself. An OpenCode Go key enables Go. Explicit
  `false` settings win. The first interactive start lists once which optional keys are missing.
- **Live model data.** The model list comes from each provider's models endpoint. Limits and
  prices the provider lacks come from OpenRouter's public model list. The last fetch is cached on
  disk. An unknown limit uses a cautious default (128K context, 8K output). An unknown price
  stays usable and is recorded as uncertain spend.
- **No hard-coded catalog.** The built-in OpenAI, Anthropic and ChatGPT model rows are removed.
- **ChatGPT plan.** The plan's limits are advisory: warning at 80% and 100%, recorded, never a
  refusal. The plan's model list is read live from the Codex models endpoint (pending merge).
- **OpenRouter provider policy.** Today oxa forces zero data retention and no data collection on
  every OpenRouter request. That becomes your choice: nothing extra is sent by default, and
  `oxa.cloud.openrouter_provider` (`zdr`, `data_collection`) sets it (pending merge).
- **Limits warn.** Go usage windows warn at 80% and 100% and do not stop the request. Without
  `oxa.cloud.daily_budget_usd` there is no budget check; every request is still written to the
  private ledger.
- **Resilience.** Streams may be silent for 15 minutes (`httpIdleTimeoutMs`). Retries default to
  10. A cloud reply with no text and no tool call is asked once more (`oxa.emptyReplyRetries`).
- **Other.** The thinking level reaches cloud models. `compaction.profile` gives cloud sessions
  their own compaction values. The gateway refuses a request that contains a stored key.
  `oxa usage --json` prints today's spend; `--usage-log <file>` writes one line per model call.

## Local models

- **`oxa local add <model.gguf>`.** It asks the engine what the model needs (context, output,
  memory) and writes the local settings from that report. Your old settings file is backed up
  first. Anything the report cannot supply is an explained error, and nothing is written.
- **Honest no-model message.** With no model configured, `oxa` says so and says what to do (add a
  cloud key or run `oxa local add`). The default engine address is now the `oxe-server` port.
- **Small Qwen3.5 models.** `oxe` runs the dense Qwen3.5 family (0.8B, 2B, 4B, 9B) as well as the
  35B mixture models. The 0.8B model is checked against llama.cpp in CI.
- **Real-model end-to-end check.** CI serves Qwen3.5-0.8B with `oxe-server` and runs real `oxa`
  tool tasks. Numbers from a green run on a CI ARM64 runner: the cache reuses the previous prompt
  in every request (3580 of 3603, 3624 of 3665, 3833 of 3854 tokens); a direct warm request
  starts streaming in 19 ms against 1588 ms cold; a follow-up turn takes about 1 second. The
  system prompt and tool list stay byte-identical across the session (12 KB). These are CI
  numbers for a tiny model, not a speed claim.
- **Engine.** oxa starts `oxe-server` on the first request, queues requests, switches models,
  unloads when idle and stops under memory pressure. A model loads only when free memory covers
  the weights and the context. oxa never downloads a model. Sampled MTP decoding is available
  (`--mtp-sampled`, off by default). The state cache is sturdier.

## Safety

- **No secret publishing.** `oxa work --publish` scans every commit it would push, including
  content added and later removed, and refuses on secret files, private keys, token shapes and
  secret-named values. The error names the file and line, never the value. There is no override.
- **Fail-safe settings.** If your user settings file is unreadable or invalid, oxa starts with
  offline on, sandbox network off, remote engines off and project trust never, and says how to
  recover. A missing file or `{}` is normal.
- **Approvals and confirms.** A typed yes answers only a dialog that was shown. Commands started
  by the model (`oxa work --publish`, `oxa report-issue`) verify the confirm broker before they
  trust it. `report-issue` shows the exact text in a dialog for approval.
- **Extension prompts.** An extension that runs a command in a directory outside the session
  directory now asks, like an outside write. Yolo never asks.
- **Settings and credentials.** A project settings file cannot set user-only keys. The sandbox
  denies more credential files. `GH_TOKEN` reaches only `gh` commands. Streamed command output is
  redacted without leaking how much of a secret was guessed.
- **Dangerous commands.** Parsed-command rules ask before destructive commands (`oxa.approval.dangerous`).

## Rust-only

- The Python controller (`oxc`), its installer, diagnostics, tests and CI jobs are deleted.
- Release staging, licence collection, SBOM and smoke checks run as shell scripts in a Python-free
  build container. The built-in `ox-llm` skill and `oxa report-issue` work with `oxa` alone.
- The memory-latency boot helper is a native tool. Engine proof binaries and unused tools are gone.

## Developer and CI

- **Dev builds** are versioned as the next patch (`v0.2.1-dev.<sha>`) so they sort after the
  release. `tools/lab/dev-update.sh` picks the highest version.
- **CI speed.** Duplicate lane runs are skipped when a PR exists, superseded runs are cancelled,
  macOS runs only for relevant paths, and the engine test timing group is narrower.
- **CodeQL** runs on `main`, weekly and on demand, not on every pull request.
- **Checks.** An end-to-end job with a real small model (see Local models), an oracle job that
  compares `oxe` with llama.cpp, and a performance and cache baseline.
- **Packaging.** Combined ARM64 and x86_64 archives with `SHA256SUMS`, an SBOM and build
  provenance, plus Arch recipes. Every `OXA_`, `OXE_`, `OXF_` and `OXI_` variable is documented.
- **ox AI panel.** The panel moved next to oxa (`oxa/omarchy-panel/`) with a frozen data
  contract. `oxa status --json` and `oxa usage --json` feed it. It is not packaged yet.

## Behaviour changes

Defaults that changed since v0.2.0. Each can be set back in your user settings.

- Retries: `retry.maxRetries` 3 to 10. Stream silence limit `httpIdleTimeoutMs` 5 to 15 minutes.
- `oxa.bash.maxJobs` and `oxa.subagent.maxChildren` are warning thresholds. Above them the work
  still starts (children queue) and the result warns.
- The goal idle pause is opt-in (`oxa.goal.idlePause`, default false). Unknown token usage is
  recorded, not counted as exhausted.
- Cloud sessions scale the tool output, subagent result and soft token caps with the model's
  window when you did not set them.
- `oxa.wait.maxSeconds` 1 hour to 24 hours. `oxa.subagent.remoteConcurrency` 4 to 8. Lead shadow
  on by default.
- Keys switch on the cloud gateway and discovery. The built-in model table is gone; a missing
  provider endpoint now shows up as an unavailable model, not a stale row.
- OpenRouter: forced zero data retention is removed; set `oxa.cloud.openrouter_provider` to
  keep it (pending merge).
- An unusable user settings file starts oxa offline and restricted instead of with empty settings.
- Interactive runs on Linux have no OS sandbox unless you pass `--sandbox`. Unattended runs keep it.
- `wait` is a default tool in every session (`oxa.tools.wait: false` removes it).
- Workers inherit the lead's mode instead of workspace, and workspace and auto workers can push
  their own branch and open their own pull request (pending merge).
- The default engine address is the `oxe-server` port, and with no model configured oxa exits
  with a clear message.
- Interactive `--max-time` and `--max-tokens` are accepted. An explicit `--yolo` or `--auto`
  in the home directory warns once and goes on.

## Not in the release binaries

- LAN sharing of models (`oxa share`) is in the source tree behind a build feature. The release
  binaries do not include it.
- Image generation (`oxi`) and the Flash engine are not in the combined archive.

## Known issues

- macOS: `main` does not build for macOS because `oxa-session`'s inbox uses Linux-only inotify
  and eventfd. No macOS asset is published. Cloud-only groundwork (no-sandbox bash, MCP over
  stdio, ChatGPT token store) is in the tree.
