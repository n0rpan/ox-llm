Doors (the only places these things may happen)
- append an entry / push to the wire: `append_entry`
- call the engine: `request` (wrapped by `chat_with_retry`)
- rebase: `compaction.rs` (compaction), `navigate.rs` (leaf_move), `epoch.rs` (epoch), `exec.rs` guard path (extension), context-edit application in `navigate.rs`
- open an epoch: `epoch.rs`, between runs only
- text that reaches the model: `prompt.rs`, `oxa-tools/src/descriptions.rs`, `oxa-compact/src/prompt.rs`

Engine contract (as the real controller and oxe engine implement it)
- Discovery (`oxa_engine::parse_info`): the controller's `/_local/status` gives the context as `context.cap` / `context_size`, the queue as `queued_requests`, the compaction point of the selected mode as `context.modes[].compact_at` (used as the soft compaction limit unless `oxa.compaction.softTokens` is set) and no output limit (oxa uses `min(16384, n_ctx / 4)`). Capabilities come from the engine's `/props` `oxe_hints`.
- Target-specific metadata and budget (X3): `Engine::info(Some(model))` gives the limits of the selected model, also when it is not loaded, when the engine publishes them (the controller's per-model `model_limits`; `EngineInfo::limits_for` names the model). `Session::open`, a model switch (`set_model`) and `/reload` read it and recompute `CompactPolicy` (`session::refresh_budget`) from that info and the current `compaction.*` settings; `exec::request` takes its default `max_tokens` from it. So the first request after a switch to a smaller model already fits that model's context and output limit. `prefill_only` (a property of the loaded engine) is the reported one once the target is loaded, else only when both the previous and the reported engine advertise it. An engine without per-model limits describes only its loaded model: then the budget is provisional, each limit the smaller of the previous and the reported one, re-read before and after each run until the engine reports the target (a mid-run overflow goes through C2 overflow recovery). An `info` failure keeps the previous metadata with a notice. Auto-compaction: the runtime switch `set_auto_compaction` overrides `compaction.enabled` (`CompactPolicy.enabled` follows it); on `/reload` only a changed `compaction.enabled` resets the switch. The hard-overflow path compacts regardless. No budget change touches the prefix bytes (W3: only the model switch opens an epoch).
- Idle prefill (H6, `max_tokens: 0`) is sent only when `oxe_hints.prefill_only` is advertised; otherwise it is skipped. It carries `X-Oxe-Snapshot: keep` (H4) only when `caps.snapshot_keep > 0` (F11).
- F4: capabilities a loaded engine reports only on `/props` are re-read (`refresh_budget`) once after the first successful reply while `prefill_only` is still false, and once after a request that recovered from `engine_busy` / `engine_down` / 5xx (a model load or restart; `Gate::reread_info`). No `info` call per request otherwise. `budget_confirmed` itself is unchanged: `EngineInfo` carries no "loaded" flag, so the first-reply re-read is what closes the "selected but not loaded" hole.
- F11: after an H4 request (idle prefill, park) a kept checkpoint is recorded in `Stats::last_snap_pos`; `snap_pos: null` is one `Info` notice ("the engine kept no checkpoint for this <kind> request; a later restore may prefill more"), never an error.
- F6: a `Length` stop with `usage.prompt + usage.completion >= n_ctx - 1` was cut by the full CONTEXT: `chat_with_retry` treats it as `context_overflow`. The cut reply is never pushed (W2): it is stored as `Shown { why: cut }` (the entry that closes the open message for reducers), a new pending `MessageStart` opens the retry's message, then overflow compaction (foreground) and one retry; a second context-full cut is returned and the loop stores `Shown { why: failed }`. A generating request may not end in an assistant message (oxe answers 400; only an H6 prefill may), and W1 rules out rewriting the cut reply or inventing a user turn. A cut reply without tool calls ends the run with stop reason `length`; tool calls in a cut reply are not run and each gets `tool_errors::TRUNCATED`, after which the loop continues. `oxa_fake` (both engines) enforces the 400 rule.
- Write-class calls hold their `Access::Write` paths in a process-wide `MutationQueue` while they run (C7). The lock identity is the canonical path (`MutationQueue::key`, X4), computed before sorting and deduplicating, so aliases of one file (symlink, `./a`, `d/../a`) are one lock and the locks are taken in identity order.

Request gate and background work (S1, ENG-001 / ENG-002; `Shared::gate`, type `queue::Gate`)
- `exec::request` holds `Gate::in_flight` from its hooks to the end of the reply. A second request of the same instance meanwhile (re-entrancy: a host request such as `ParkSession` served during a request's hooks) is refused with `busy` and never sent.
- Background requests are exactly: the threshold (after-reply) summary and idle prefill (after a compaction, after a leaf move). They are sent with `X-Oxe-Priority: background` and the token `Gate::bg_cancel`; every other request (the run, `/compact`, overflow recovery, the S3 pre-switch compaction, a branch summary, the park) is foreground, without the header, cancelled only by `abort` (F12).
- `Handle::steer` / `Handle::follow_up` queue first and then set `bg_cancel`; `Handle::abort` sets `cancel` and `bg_cancel`. `Shared::begin_background` (called right before each background request) clears `bg_cancel` and refuses to send when input is already queued or the run was aborted; `Session::begin` clears it too. A cancelled idle prefill is skipped silently (no notice, no usage entry). A cancelled threshold summary leaves the wire unchanged and emits `CompactionEnd { aborted: true }`; it is decided again after the next run.
- `Session::prompt` runs queued input that arrived during its background phase before it returns (loop: follow-ups, after-reply compaction, queued steering + follow-ups, until the queues are empty or an abort). For the other paths there is `Session::run_queued(sink, ui) -> Result<Option<RunEnd>, OxaError>`: runs queued steering and follow-up messages as one run when the session is idle (`None` when nothing is queued; `busy` during a run; emits `AgentSettled` when it ran). Front ends call it after `Session::navigate` and `Session::compact` (to be wired in `oxa-interactive`).

Model switch (S3 / O-145 / ENG-004; `session::switch_model`, the one door for `set_model`, `set_model_with`, `HostAction::SetModel`, RPC)
- `plan_switch` / `Session::plan_model_switch`: `context_tokens` = the last `prompt + completion`, or after a rebase an estimate through the tokenizer (prefix + wire, content only). When the engine publishes the target's limits (`limits_for == target`): `target_ctx`, `target_hard` = the target's `policy_for_model(..).hard` (`n_ctx - max_output - reserveTokens`, at least 1024), `over_cap = context_tokens > target_hard` (the first request with `max_output` of room, or the summary it would need with the reserve, would not fit). Unknown limits: `over_cap = false`, the provisional-minimum rule of `refresh_budget` applies. `cold_tokens = context_tokens`, `est_secs = prefill_estimate_secs(cold_tokens)`.
- Over the cap, `OverCap::Refuse`: nothing changes, nothing is sent; `invalid` "the conversation is about <n> tokens; <target> takes at most <hard> (context <ctx>): compact first, fork or cancel" (hint `compact_first`).
- Over the cap, `OverCap::CompactFirst` (default of `set_model` and the host): an `Info` notice, then a foreground compaction on the SOURCE model (reason `Manual`, W5 append-style, no idle prefill), sized for the TARGET: summary `max_tokens` = min(source, target `summary_max`); kept tail = the target's `keep_tokens`, at most `target.soft - prefix - summary_max` tokens, else no tail (summary only). The switch proceeds only when the wire was rebased AND prefix + new head (estimated) <= `target_hard`; otherwise the model is unchanged and the error says "the model is still <source>: ...". The session is claimed (`busy`) during that compaction so `abort` reaches it.
- Then: `ModelChange` entry, `ModelSelect` event, `refresh_budget`, hook point `ModelSelect` `{model, previousModel}` (before the epoch reads the hook sets' tools), and the epoch with ONE notice "new prefix epoch (model): <target> prefills about <n> tokens cold (~<s> s)"; `PrefixEpoch.reprefill_tokens` is the same `<n>`. Other epochs: "new prefix epoch (<reason>): about <n> tokens to prefill again (~<s> s)".
- Leaf move (`navigate`): before the idle prefill one `Info` notice "leaf moved: the engine prefills about <n> tokens (~<s> s) now, in idle time" ("with the next request" without H6). `<n>` = estimated tokens of the new branch minus what the engine can restore: `Stats::last_snap_pos` when it lies in the part both branches share, else the prefix.

Compaction settings (S4, CMP-015 / SET-026)
- `compaction.modelOverrides` is an object keyed by engine model id. The entry of the session model, when an object, overrides `reserveTokens` and `keepRecentTokens` in the policy (`session::policy_for_model`). An entry that would send the summary to another model (`"<id>": "<other>"` or `{"model": "<other>"}`) is ignored: one `Warning` notice per session and epoch ("compaction.modelOverrides: summaries on <other> are not supported (one model is loaded at a time); the summary runs on <model>"), and the summary runs on the session model. Entries of other models change nothing.

Subagents (E11, `subagent.rs`; policy: OXA-ENGINE-SUPPORT sec. 2)
- `SubagentHooks` (enabled by `oxa.subagent.enabled`, built by `oxa-cli`) offers one `Direct` tool `subagent` with pi's shapes `{agent, task}`, `{tasks}` and `{chain}` (`{previous}`), parameters `agent`, `task`, `tasks`, `chain`, `cwd` (pi's `agentScope` / `confirmProjectAgents` are dropped: project agents load only from a trusted project). The agent list (sorted) is part of the description, so it is configuration only (W3). The tool's source is `Extension("oxa:subagent")`, class `Exec` (plan mode refuses it) and it `needs_ui`, so the loop never runs it in a parallel batch.
- Concurrency 1: a lock per hook set holds the whole call; `tasks` run in call order (progress `subagent k/n, queued`), more than 8 are refused with pi's text. Each child is `<oxa> --mode json -p --no-session --model <session model> --permission-mode <mode> [--tools ..] [--append-system-prompt <prompt>] "Task: <task>"` in its own process group with `OXA_SESSION_HINT=<parent id>.s<n>`, `OXA_SUBAGENT_DEPTH=1`, `OXA_CHILD_SOFT_TOKENS=<n>`. An agent's own `model:` is ignored with a warning notice.
- Host calls: `EngineLimits` at the start of a call; `ParkSession` once, right before the first child; `ClearEngineHint(hint)` after every child (also after a failure or abort; an error is a warning notice). Child soft limit = min(`oxa.subagent.softTokens` (24000), the parent's `compactAt`, context window - 1).
- Result: the final assistant text per child (pi's single / chain / `Parallel: k/n succeeded` texts), capped at `oxa.subagent.resultCap` (6144) bytes on a UTF-8 boundary + `[subagent output truncated: <n> bytes, full text in <spill_dir>/subagent-<sha256>.txt]`. Child JSON records become progress lines on `live` only.
- Abort: the cancel token or `Hooks::shutdown` sends SIGTERM to the child's group (`kill` binary; no `unsafe`), SIGKILL after 2 s; queued tasks never start. A group left behind by a finished child is killed too.
- Declaration: not declared when the session model's context window is below 32000 unless `oxa.subagent.smallContext`. `tools()` runs on the session thread, where `Host::call` cannot be answered, so the window is learned through `EngineLimits` in `attach` and when `SessionStart` / `ModelSelect` fire. The switch door fires `ModelSelect` after the target's limits are read and before the epoch, so the declaration follows a model switch; an unknown window declares the tool.

Testing: every module is testable with `oxa_fake::ScriptedEngine`, `oxa_session::MemStore`, `oxa_proto::{NoHooks, HeadlessUi, VecSink}` and `oxa_sandbox::NoSandbox`; `oxa_fake::check` verifies W1-W6 on the recorded requests.
